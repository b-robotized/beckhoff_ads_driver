Add an ADS device-notification read path so PLC state is pushed to a background callback and cached, instead of issuing a synchronous SUM read every control cycle. This removes the network round-trip from `read()`, decoupling the control-loop rate from network latency. It is now the default (`read_mode=notification`); set `read_mode=polling` on the `<hardware>` tag to restore the synchronous SUM read. Per-state-interface tuning is available via the `notify_mode` (onchange/cyclic), `notify_cycle_ms`, and `notify_max_delay_ms` URDF parameters. The write path is unchanged.
